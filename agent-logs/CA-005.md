# CA-005 — JSON task schema with HTML presentation page

## Summary
Created a simple JSON Schema for task details (task ID, name, short description, status, completed steps, tools used) and a static HTML page that presents it: a header, a window showing the schema, and field descriptions below. The project lives in `json-cursor-template/`.

## Actions
- Synchronized with `origin/main` and read `AGENTS.md` and `.cursor/WORKFLOW.md`.
- Added `json-cursor-template/task-schema.json` (JSON Schema draft 2020-12).
- Added `json-cursor-template/index.html` with a header, schema window, and field descriptions.
- Added `json-cursor-template/styles.css` (plain CSS, light/dark via `prefers-color-scheme`).

## Decisions
- Placed the files at repository root in `json-cursor-template/` because this Git repository is `cloudagents` and is checked out at `/workspace`. That is the Cursor counterpart of `josn-template/` (Codex) and `josn-claude-template/` (Claude). A nested `cloudagents/` directory was not created.
- Kept the page to plain HTML and CSS with no JavaScript. The schema is embedded in the page so it also works from `file://`.
- Used English snake_case field names (`task_id`, `name`, `description`, `status`, `steps_completed`, `tools_used`) following the repository language rule.
- `status` uses the repository workflow values: `todo`, `in_progress`, `completed`, `partial`, `blocked`.
- `task_id` is constrained to `CA-<number>`; `additionalProperties: false` keeps the format strict.
- Field descriptions use a definition list rather than a table or card grid, so the Cursor page is visually distinct from the existing Codex and Claude templates.

## Validation
- Parsed `task-schema.json` with Python `json`.
- Confirmed the schema text embedded in `index.html` matches `task-schema.json`.
- Checked the schema with `jsonschema.Draft202012Validator.check_schema`. A valid sample produced no errors. Invalid samples were rejected: unknown status, extra property, empty name, non-CA task ID, and missing `tools_used`.
- Served the page with `python3 -m http.server` and opened it in Chromium. Confirmed header, schema window, and all six field descriptions at desktop width (1280px) and mobile width (390px).
- After the first browser pass, enabled `white-space: pre-wrap` on the schema window so long JSON lines wrap instead of requiring horizontal scrolling.
- Not performed: W3C HTML validator, cross-browser testing beyond Chromium.
