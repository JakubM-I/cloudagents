Schema fragment

The task fields, one piece at a time

The complete example stays on the left. The cards follow that example from top to bottom. The lines that belong to the card you are reading are marked in the sample.

01

properties

The document is a single JSON object. Its only member is the JSON Schema keyword properties, which maps each field name to the rules for that field. This fragment names three fields: task_id, name, and description.

{
  "properties": {
    "task_id": { … },
    "name": { … },
    "description": { … }
  }
}
properties
An object. Each key is a field name, and each value is a schema for that field. This fragment does not set "type": "object" and does not list required fields. A full schema usually adds both next to properties.

02

task_id

The identifier of one task. It is the value that ties a task to its branch, task log, and pull request.

"task_id": {
  "type": "string",
  "description": "Unique task identifier in the format CA-<number>.",
  "pattern": "^CA-[0-9]+$",
  "examples": [
    "CA-004"
  ]
}
type
Assertion. The value must be a JSON string.
description
Annotation. Sentence for a person reading the schema. Validators do not check it.
pattern
Assertion. The whole string must match ^CA-[0-9]+$: CA-, then one or more digits, and nothing else. CA-004 matches. ca-004, CA-, and CA-004-extra do not.
examples
Annotation. CA-004 is a sample for documentation. The keyword does not accept or reject data.

03

name

A short title a person can scan in a list of tasks.

"name": {
  "type": "string",
  "description": "Short, human-readable task name.",
  "minLength": 1,
  "examples": [
    "Create a JSON task template"
  ]
}
type
Assertion. The value must be a string.
description
Annotation. Explains that the field is a human-readable name.
minLength
Assertion. At least one character, so "" fails. A single space passes: the keyword counts characters and does not trim whitespace.
examples
Annotation. One sample title, written as a short imperative phrase.

04

description

A brief summary of what the task should accomplish.

"description": {
  "type": "string",
  "description": "Brief summary of the task goal or scope.",
  "examples": [
    "Define a JSON schema for task details and present it on a static HTML page."
  ]
}
type
Assertion. The value must be a string.
description
The outer key is the field name. The inner key is the JSON Schema keyword that documents the field. They are two different members.
examples
Annotation. A sample summary. This field has no minLength, so an empty string still satisfies the rules shown here.
